# Story 1.1.5: ReplyKeyboard Persistent Menu

Status: done

**Story Key:** `1-1.5-reply-keyboard-persistent-menu`
**Epic:** 1 — Первое касание и знакомство с продуктом

**Коротко:** Реализовать постоянное меню навигации через Telegram ReplyKeyboard с 4 основными кнопками, которое всегда видимо пользователю. Это промежуточная история, добавленная в спринт для упрощения навигации до полной реализации structured flow в Story 1.4.

## Story

As a гость,
I want видеть постоянное меню с основными действиями внизу экрана,
so that легко переключаться между разделами бота без поиска команд.

## Acceptance Criteria

1. **Given** пользователь запустил бот и прошёл welcome-сценарий (Story 1.1)
   **When** бот отправляет любое сообщение после приветствия
   **Then** вместе с сообщением отображается ReplyKeyboard с 4 кнопками:
   - 🔍 Поиск квартир
   - 📋 Мои бронирования
   - ❤️ Избранное
   - ❓ Помощь

2. **And** ReplyKeyboard настроен как persistent: `is_persistent=True`, `resize_keyboard=True`
   **And** клавиатура всегда видна, даже когда основная клавиатура скрыта

3. **And** при нажатии на кнопку "🔍 Поиск квартир":
   - Бот запускает demo search flow (Story 1.2)
   - Отправляет подсказку: "Напиши, что ищешь: район, даты, бюджет"

4. **And** при нажатии на кнопку "📋 Мои бронирования":
   - Бот показывает заглушку: "Раздел 'Мои бронирования' появится в Epic 4. Пока можешь попробовать поиск."

5. **And** при нажатии на кнопку "❤️ Избранное":
   - Бот показывает заглушку: "Раздел 'Избранное' появится в Epic 3. Пока можешь попробовать поиск."

6. **And** при нажатии на кнопку "❓ Помощь":
   - Бот показывает краткую справку (переиспользует существующий /help handler из Story 1.1)

7. **And** весь пользовательский текст строго на русском языке (FR9)

8. **And** ReplyKeyboard не удаляется при переходах между разделами — остаётся постоянной

9. **And** fail-soft behaviour сохраняется на всех шагах:
   - При исключении в handler — логировать ошибку и отправлять пользователю дружелюбное сообщение
   - Всегда отвечать на message с ReplyKeyboard

10. **Non-goals для Story 1.1.5:**
    - Полноценная навигация с navigation stack (будет в Story 1.4 после переработки)
    - Согласие на обработку ПД (будет в переработанной Story 1.4)
    - Динамическое изменение кнопок в зависимости от роли (гость/хост — будет в Epic 2)

**Цель Story 1.1.5:**
- Добавить **постоянное ReplyKeyboard меню** с 4 основными кнопками
- Заменить часть функциональности, запланированной в Story 1.4, на более простое решение
- Дать пользователю быстрый доступ к основным разделам бота без ввода команд

**Почему ReplyKeyboard вместо inline-кнопок:**
- **Всегда видна** — пользователь не теряет меню при скролле
- **Привычный UX** — стандартная клавиатура Telegram, как в большинстве ботов
- **Быстрое переключение** — одно нажатие для перехода в раздел
- **is_persistent=True** (aiogram 3.24.0) — клавиатура не скрывается даже когда системная клавиатура открыта

**UX-принципы:**
- Максимум 4 кнопки в ReplyKeyboard (не перегружать меню)
- Короткие названия с эмодзи для наглядности
- Заглушки для будущих разделов (Мои бронирования, Избранное) — не скрывать возможности, но показать что они в разработке

### Technical Requirements

- **Платформа:** Telegram Bot (aiogram 3.24.0)
- **ReplyKeyboard:** `ReplyKeyboardMarkup` с параметрами:
  - `is_persistent=True` — всегда видна
  - `resize_keyboard=True` — оптимальный размер под экран
  - `input_field_placeholder="Напиши запрос или выбери действие"` — подсказка в поле ввода
- **Кнопки:** 4 штуки, расположение 2×2
- **Message Handlers:** `@router.message(F.text == "🔍 Поиск квартир")` для каждой кнопки
- **Сохранение keyboard:** Все ответы бота должны включать `reply_markup=_build_main_reply_keyboard()`
- **Error Handling:** Всегда логировать исключения, отправлять fail-soft сообщения + ReplyKeyboard
